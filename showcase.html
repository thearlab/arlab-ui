Design system rules this package encodes

From ARLAB's anti-AI-slop playbook, plus what this pass fixed.

01Cards are the exception, not the default.Use Row/ArlabList for anything that's a list item. Reach for Card only for a genuinely independent, liftable object.
02No mono-uppercase labels on every string.Label is sentence case, normal weight. We deliberately did not copy signature-studio's uppercase mono product-name style into NavbarBrand for this reason — see the Navbar section.
03One accent, used sparingly.--accent is for small fills, dots, and primary buttons only. --accent-tint is the muted surface fill; --accent-deep is the readable text tone on light backgrounds.
04Skeletons, never bare loading text.Skeleton mirrors the real layout's shape.
05Real light and dark, not an inversion.Light is the default palette here. Dark isn't pure black.
06One primitive per concept, composed rather than configured.Card + CardHeader/CardBody/CardFooter compose like a sentence, instead of one component with twelve props.
07Type is a scale, in rem, not arbitrary px.Every font-size is a --text-* token so the UI still respects a user's browser text-size/zoom preference — a real accessibility mechanism, not just visual consistency.
08Every primitive defends its own layout.A Badge stays a pill even inside a stretching flex column; a Row title truncates instead of colliding with a trailing control. Found the hard way — see the Card section.

Signature details

The things that make this a designed system instead of a competent default: three radius tiers with a reason (not one flat rounding everywhere), a mono face that does real identity work, and a corner-bracket motif used exactly twice.

Navbar

The lockup at the very top of this page is <Navbar><NavbarBrand logo name dot /><NavbarSpacer />...anything...</Navbar>. Navbar is just a flex row — NavbarBrand is the only opinionated piece. Everything after NavbarSpacer is arbitrary children: a role badge, an icon button, an avatar here, but it could be search, nav links, anything.

Icons

A custom set, one shared recipe: 24×24 canvas, 1.6 stroke (thinner than the usual 1.75-2 — reads more precise, less cartoonish at small sizes), round caps and joins. 21 icons, covering what a lead console actually needs.

Color

Every value below is a CSS custom property from styles.css — components never hardcode a hex.

Type

A rem-based scale (--text-xs through --text-3xl), so it scales with a user's font-size preference — not just fixed pixels.

Dropzone

No dashed border — that's the single most generic "AI file upload" pattern there is. A solid tonal panel, an actually-elevated icon target with its own shadow, and an explicit "Browse files" pill instead of a control that only works if you click the right invisible spot.

Dialog, Toast & LoadingBar

Dialog: backdrop blur, closes on Escape or a backdrop click, returns focus on close. Toast: a bottom-center pill, always dark-on-light or light-on-dark regardless of page theme. LoadingBar: a thin top-of-page indeterminate bar for a route change or long fetch — ported from theARLab's site loader, gradient accent→orange sliding across.

Skeleton

Mirrors the row layout above, at rest. Never a bare "Loading…" string.

Tabs

Replaces arlab-studio's two divergent tab systems (a nav-pill system and a plain-underline system). The underline now slides to the active tab instead of just recoloring, and the track scrolls horizontally instead of wrapping — the Detail view's 8 tabs used to wrap awkwardly.

Popover, dropdown menu & combobox picker

Neither app had an actual floating action menu. DropdownMenu is built on a generic Popover. ComboboxPicker hardens arlab-studio's inline reference-picker (search + list) with arrow-key navigation it previously lacked.

Command palette

A Cmd/Ctrl+K searchable modal, ported from arlab-docs. Click the search button, or press ⌘K.

Nav tree

A collapsible, nested, route-aware sidebar nav — arlab-docs' Sidebar pattern, generalized. The branch containing the active item auto-expands.
